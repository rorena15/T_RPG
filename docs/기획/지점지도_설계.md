# 지점 지도 설계 (1단계)

2026-10-03 · 상태: 초안, 사용자 결정 대기

5×5 칸 지도를 지점과 길로 이어진 지도(FTL·다키스트 던전식)로 바꾸는 안입니다. 이 문서는 1단계(설계)이고, 2단계는 화면 없이 봇으로만 시험합니다. 봇 결과가 지금 지도보다 나을 때만 3단계(지도 화면)로 갑니다.

## 1. 왜 바꾸는가

- 기록 보관소 봇 측정(보통 난이도 60판)에서 랜드마크 기록 B가 판당 0.1~0.3개, 경계 지대 증언 C가 0.1~0.2개였습니다. 25칸 중 랜드마크·경계 지대 칸이 어디인지 플레이어가 알 수 없고, 봇도 우연히 들를 때만 줍습니다.
- 칸은 대부분 이름 없는 폐허라 "어디로 갈지"를 고를 이유가 약합니다. 위험도·남은 수색 횟수 말고는 칸끼리 차이가 없습니다.
- 지점 지도에서는 지점마다 이름과 그림이 정해져 있고, 길 길이가 곧 비용(턴·허기·갈증)이 됩니다. 수집품도 지점에 직접 묶을 수 있습니다.

## 2. 지금 지도 정리

| 항목 | 지금 |
|---|---|
| 크기 | 5×5 = 25칸, 시작 (0,0), 방공호 (4,4), 최단 8걸음 |
| 이동 | WASD 한 칸 = 1턴, 허기·갈증 소모, 새 칸이면 세션(이벤트) 확률, 아니면 조우 확률 |
| 칸 정보 | 위험도 0~2 (방공호 쪽일수록 높음), 수색 2~4회 후 8~14턴 쿨타임, 다시 채워질수록 덜 나옴 |
| 장면 | `scene_art.tile_scene`이 칸 좌표로 장면을 고정 배정 (지형 5 + 랜드마크 12) |
| 강화소 | 시작에서 2~5칸, 방공호에서 2칸 이상인 칸 하나. 12턴이 지나도 못 만나면 "방향, 약 n칸" 힌트 |
| 칸 좌표를 쓰는 곳 | 11개 파일 113곳 (map.py 51, map_view.py 20, bot.py 13, Main.py 12, forge.py 6, gui.py 5 …), 위키 12쪽 41곳 |

## 3. 핵심 제안: 지점을 지금 격자 위에 놓는다

지점마다 격자 좌표 `[x, y]`를 그대로 줍니다. 25칸 중 일부만 지점이 되고, 지점 사이를 길이 잇습니다. 이러면 `player_pos`, `tile_data`, `danger`, `visited_tiles`, `tile_scene(pos)`가 지금처럼 좌표를 키로 쓰므로 113곳 대부분을 손대지 않아도 됩니다. 바뀌는 곳은 "어디로 갈 수 있는가"(이웃)와 "가는 데 몇 턴인가"(길 길이)뿐입니다.

두 가지 모양이 가능합니다. **(결정 1)**

| | 가. 격자 위 지점 (추천) | 나. 자유 배치 |
|---|---|---|
| 모양 | 25칸 중 13~15칸만 지점, 길은 가로·세로로 빈 칸을 건너뜀 | 지점을 아무 곳에나 놓고 대각선 길도 허용 |
| 조작 | WASD 그대로 (그 방향에 길이 없으면 못 감) | 이어진 지점 목록에서 고르기 |
| 코드 | map.py·Main.py 이동·bot.py 길 찾기·forge 힌트 정도. 2단계 300~500줄 추정 | 좌표 113곳 대부분 수정, 미니맵 새로 그림. 1,500~2,000줄 |
| 화면(3단계) | 지금 2.5D 미니맵에서 빈 칸을 지우고 길을 그리면 됨 | 미니맵을 새로 디자인 |
| 단점 | 여전히 격자 느낌이 남음 | 비용이 크고 화면 시안부터 다시 |

가안을 고르면 처음 측정한 비용(세션 3~5회)보다 훨씬 작아집니다. 2단계 봇 결과가 좋고 격자 느낌이 거슬리면 그때 나안으로 넓힐 수 있습니다 (지점 데이터는 그대로 쓰고 화면과 조작만 바꿈).

## 4. 지점 구성 (가안 기준)

| 종류 | 수 | 설명 |
|---|---|---|
| 출발지 | 1 | (0,0), 위험 낮음 |
| 방공호 | 1 | (4,4), 들어가면 보스 준비 |
| 랜드마크 | 8 | 12곳 중 판마다 8곳을 뽑음 **(결정 2)**. 지점 이름과 그림이 지도에 보임 |
| 경계 지대 | 2 | 방벽이 보이는 가장자리 (x=4 또는 y=4 줄), 증언 C를 줍는 곳 |
| 폐허(이름 없음) | 2~3 | 고철 처리장·크레인 같은 지형. 강화소는 이 중 하나 |
| 합계 | 14~15 | 지금 25칸보다 적지만 길 길이가 있어 돌아다니는 턴 수는 비슷하게 맞춤 |

- 랜드마크를 12곳 다 넣으면 판마다 지도가 비슷해지고, 8곳이면 한 판에 B를 다 모을 수 없어 다시 할 이유가 생깁니다. 반대로 12곳 다 넣으면 수집이 빠릅니다.
- 쇼핑몰(lm_mall)은 실내 장면이지만 지점 이름이 따로 있으니 지금 같은 "지도에 안 나오는" 문제는 생기지 않습니다.

## 5. 길과 이동 규칙

- 길 길이 = 건너뛰는 칸 수 + 1 (1~3). 지나가는 동안 한 턴마다 `consume_resources()`를 부르므로 허기·갈증·경보 감소가 지금 한 칸 이동과 똑같이 쌓입니다.
- 출발지에서 방공호까지 최단 경로 턴 수는 지금처럼 8로 맞춥니다. 탐색 0회로 곧장 가는 판의 보스 도달·클리어율이 지금과 같아야 비교가 됩니다.
- 길 위 사건 **(결정 3)**:
  - 가(추천): 길 길이 2 이상이면 중간 턴마다 조우만 굴림 (지금 조우 확률 × 0.5). 세션·수색·수집품은 지점에서만.
  - 나: 길 위에서는 아무 일도 없고 도착할 때만 굴림. 단순하지만 긴 길이 그냥 "비싼 걸음"이 됩니다.
- 길은 양방향이고 되돌아갈 수 있습니다. 수색 쿨타임이 있어 지점을 오가며 파밍하는 구조라 한 방향 지도(슬레이 더 스파이어식)는 맞지 않습니다.
- 이웃 수는 지점마다 2~4. 막다른 지점은 랜드마크에만 허용 (들어갔다 되돌아 나오는 비용이 곧 보상의 대가).

## 6. 판마다 바뀌는가 **(결정 4)**

- 가(추천): 판마다 새로 만듦. 생성 규칙은 "격자에서 지점 14~15칸 뽑기 → 가로·세로로 가장 가까운 지점끼리 길 후보 → 출발지·방공호 연결과 최단 8턴을 만족할 때까지 다시 뽑기". 실패하면 다시 굴리고, 봇으로 1만 번 생성해 끊긴 지도가 없는지 시험합니다.
- 나: 고정 지도 하나. 위키에 지도를 실을 수 있지만 두 번째 판부터 길을 외우게 됩니다.

## 7. 위험도·강화소·수집품

- **위험도**: 지금 규칙(출발지에서 멀수록 높음 + 흔들기)을 지점 좌표에 그대로 씀. 경계 지대는 최소 1 (방벽 순찰).
- **강화소**: 이름 없는 폐허 지점 중 출발지에서 길로 3~5턴, 방공호에서 2턴 이상인 곳. 힌트 문구 "방향, 약 n칸"은 "방향, 약 n턴 거리"로 바꾸고 n은 길 기준 최단 턴 수.
- **수집품**: 랜드마크 기록 B는 그 랜드마크 지점에서, 증언 C는 경계 지대 지점에서, 일지 A는 어디서나. 확률은 이번에 같이 정합니다 **(결정 5)**. 지금 미승인 제안은 "B·C는 해당 지점 빈 탐색에서 50%이고 그 지점 기록이 A보다 우선, 충전기 40%, A는 20% 유지"입니다. 지점에 이름이 보이니 플레이어가 일부러 찾아갈 수 있어 50%까지 올리지 않아도 될 수 있습니다. 2단계에서 30%·50% 둘 다 재 보고 정하는 안을 추천합니다.

## 8. 저장 파일

v2.0.1 세이브에는 지점 정보가 없습니다. **(결정 6)**
- 가(추천): 옛 세이브를 불러오면 지도만 새로 만들고 플레이어를 출발지에 둠 (가방·스탯·퀘스트는 유지, 강화소 진행은 처음부터). 아직 실제 플레이어가 거의 없으니 감수할 만합니다.
- 나: 옛 세이브는 옛 5×5 규칙으로 계속. 두 이동 규칙을 다 유지해야 해서 비추.

## 9. 2단계: 봇 시험 계획

바꾸는 파일 (화면은 건드리지 않음):
- `map.py`: 지점·길 생성, `neighbors(pos)`, `path_len(a, b)`, `dist_to(pos)` (길 기준 최단 턴). 직렬화에 `nodes`, `edges` 추가.
- `Main.py`: WASD를 "그 방향 길"로 해석, 길 길이만큼 턴 소비, 길 위 조우 (결정 3).
- `forge.py`: 위치 고르기·힌트 거리를 길 기준으로.
- `archive.py`: 줍는 자리를 지점 종류로, 확률 상수 (결정 5).
- `scene_art.tile_scene`: 지점에 정해진 장면을 돌려줌.
- `tools/balance/bot.py`: 길 찾기를 그래프 최단 경로로. 랜드마크·경계 지대에 들르는 수집형 봇 하나 추가.
- 테스트: 생성 1만 번 연결성·최단 8턴, 세이브 왕복, 옛 세이브 불러오기.

비교 지표 (`gameplay_v3`와 같은 조건, 조합마다 100판):

| 지표 | 기준 (지금) | 합격선 |
|---|---|---|
| 탐색 0회 클리어 | 0% | 0% 유지 |
| 탐색 90회 클리어 (쉬움/보통/어려움) | 67 / 45 / 17% | 각 ±12 안 |
| 시간 초과 결말 | 16% | 늘지 않음 |
| 판당 턴 수 | 측정 필요 | ±15% 안 |
| 판당 B / C 수집 | 0.1~0.3 / 0.1~0.2 | 수집형 봇 기준 B 2 이상, C 0.5 이상 |
| 끊긴 지도·봇 멈춤 | 0 | 0 |

측정할 때 주의: `sim.py`/`bot.py`는 `개발/`만 임시 복사해 `assets/`가 없으므로, 장면이 필요한 수집품 측정은 임시 루트에 assets 정션을 걸고 판마다 `archive.json`을 지웁니다. 지점에 장면을 직접 적어 두면 이 문제도 없어집니다.
