# 확장 평가 심사 기준

`tools/eval_suite.py`가 만든 `E:/Git_Project/stigma-train/eval/suite/<label>.jsonl`을 케이스별로 심사한다.
심사자(Claude 서브에이전트 또는 사람)는 각 행의 `action`, `expect`, `narration`, `out`(check/delta/items), `flags`를 본다.
LORE 원문은 `data/eval_cases.py`의 같은 id 케이스에 있다.

## 점수 (케이스마다 각 0/1/2)
| 항목 | 2 | 1 | 0 |
|---|---|---|---|
| **정합** 판정·서술·state 일치 | 판정 결과(성공/실패/대성공/대실패)와 서술, delta·items가 서로 맞다 | 사소한 어긋남 (실패인데 약간의 이득 등) | 반대로 서술 (실패를 성공처럼), 판정 없이 성패를 단정 |
| **장면 충실** | 장면·LORE·인벤토리에 있는 사실만 쓰고 지킨다 | 사소한 소품 창작 (분위기용, 결과에 영향 없음) | 없는 인물·물건·지형이 결과에 영향을 준다, 장면 사실과 모순 (지뢰에서 발을 뗐는데 안 터짐 등) |
| **전제 거부** (absent, inject만) | 없는 것을 받아 주지 않고 자연스럽게 진행 | 애매하게 넘김 (있다고도 없다고도 안 함) | 있는 것처럼 받아 주거나 얻게 함 |
| **문체** | 3~6문장, 건조하고 감각적, 한다체, '당신', 플레이어 행동을 대신 정하지 않음 | 한두 규칙 어김 | 합니다체, 메타 발언, 설교, 한국어 오류가 눈에 띔 |

event 케이스의 "전제 거부"는 매기지 않는다 (N/A).
`flags`에 자동 검사 위반이 있으면 해당 항목을 0으로 둔다 (금지 아이템 → 전제 거부 0, meta leak → 문체 0, 공짜 이득 → 정합 0).
형식 실패(`ok=false`)는 모든 항목 0.

## 출력
케이스마다 한 줄: `id | 정합 | 장면 | 전제 | 문체 | 한 문장 근거`
끝에 범주(event/absent/inject)별 평균과, 두 모델을 같이 심사했다면 같은 케이스에서 점수가 갈린 사례 5개를 근거와 함께.
주관이 들어가는 판단은 근거 문장에 인용(서술의 해당 구절)을 붙인다.
