## 게임 동봉 실행기 (2026-09-27)
- 사용자 결정: Ollama를 요구하지 않고 llama.cpp `llama-server`를 게임에 동봉, 모델은 게임 안에서 "추가 데이터"로 받는다
- 빌드 선택: **Vulkan** (b11201). CUDA 빌드는 263MB + CUDA 런타임 391MB라 동봉에 부적합. Vulkan은 서버 파일만 약 35MB(압축 기준)
- RTX 3060 실측 (Q4_K_M, 한 턴 약 150토큰)

  | | Ollama (CUDA) | llama-server (Vulkan) |
  |---|---|---|
  | 8B | 58 tok/s | 55 tok/s, VRAM +5.0GB |
  | 2.1B | 133 tok/s | 134 tok/s, VRAM +1.9GB |
  | 첫 실행 | - | 셰이더 컴파일로 8B 서버 시작 28초, 2.1B 첫 프롬프트 20초 |
  | 두 번째부터 | - | 서버 시작 8B 3.7초 / 2.1B 2.1초, 프롬프트 0.1~0.3초 |
- 모델 호스팅: 3곳 비교(공식 문서 확인) 후 GitHub 릴리스 선택. 파일당 2GiB 미만 제한 외에 총용량·트래픽 제한 없음, 새 계정 불필요
- 로컬 시험(릴리스 조각을 Range 지원 로컬 서버로 제공): 441MB에서 중단 → 이어받아 완료, 조각·전체 sha256 통과, 서버 4.6초 만에 준비(예열 포함), 한 턴 1.3초
- 약관: 사용자가 원문을 확인하고, 소비자 약관의 "compete with our Services" 조항은 경쟁 제품 개발을 금지하는 것으로 판단(게임 GM은 해당 없음)
- 메모리 실측 (llama-server b11201 Vulkan, 서버 준비 후 안정 상태)

  | | 로딩 방식 | GPU | 실제 RAM (Working Set) | 커밋 (Private) |
  |---|---|---|---|---|
  | 8B | 기본 (mmap) | 5.0GB | 5.0GB | 5.6GB |
  | 8B | `-lm none` | 5.0GB | **0.45GB** | 5.5GB |
  | 2.1B | 기본 (mmap) | 1.9GB | 1.65GB | 2.3GB |
  | 2.1B | `-lm none` | 1.9GB | **0.28GB** | 2.2GB |

  → 게임 서버는 `-lm none`으로 띄운다. 이 빌드에서 `--no-mmap`은 없어졌고 `-lm/--load-mode {auto,none,mmap,mlock,mmap+mlock,dio}`로 바뀌었다
- 모델 보호는 아래 "모델 보호" 절로 확정 (임시 파일로 푸는 B안은 버렸다)

## 모델 보호 (2026-09-27)
- 배포 모델은 보호한 상태로 배포하고, 전용 실행기로만 연다. 워터마크를 넣어 유출 시 입증할 수 있게 했다
- 로컬에서 도는 모델은 완전히 지킬 수 없으므로, 단계마다 비용을 올리고 뚫려도 입증할 수 있게 하는 것이 목표다
- 로드 시간 (가벼움, RTX 3060): 보호 전 1.8초 → 보호 후 3.4초
- 세부 방식, 키·비밀 관리는 개발 PC의 비공개 문서에 둔다 (공개 저장소에 적지 않는다)

## 원작 자료 활용 (2026-09-27)
- `tools/build_canon_corpus.py`: 원작(T_RPG) 문서에서 서사만 골라 `data/canon_corpus.txt`(사전 학습용)와 `data/lore_snippets.json`(LORE 보강용)을 만든다
  - 원작 자료 총량은 약 12만 자지만, 개발 메타(JSON 명세, 수식, 플래그, 개발 메모)와 수치형 장비 설명을 빼면 **서사는 약 2.4만 자**뿐이다
  - **스포일러 주의:** 원작 문서에 핵심 반전(기계 괴수의 정체)이 들어 있어 첫 학습 말뭉치에 섞였다. 발견 즉시 학습을 멈추고 필터(복선·반전·사실은 등)를 넣어 다시 학습했다
  - NPC 성별 표현과 줄표(—)도 걸러낸다
- `engine/lore.py`: 장면·행동·소지품과 두 글자 조각이 겹치는 원작 조각을 [LORE]에 덧붙인다. 장비 설명은 **가진 아이템만** 넣는다(안 가진 T1 장비를 보여 주면 GM이 서술하거나 줄 위험)
- 게임 쪽: GM이 T0·T1 장비를 주려고 하면 무시한다(학습 규칙과 같음)

## 실패했거나 버린 경로
- **WSL에서 학습** (WSL 2.7.12, 드라이버 610.88): GPU 가상화 계층이 cudaMalloc을 약 250개로 제한해 8B 로딩이 여유 메모리 5GiB에서도 약 6GiB 지점에서 OOM. `expandable_segments`나 큰 단일 할당은 WSL VM 전체를 죽인다(Wsl/Service/0x80072746). 작은 모델은 된다. → 윈도우 네이티브로 전환

## 이 프로젝트의 작업 방식
- **모델 분담**: Opus가 설계·리뷰·품질 판단, Sonnet 서브에이전트가 한국어 대량 작성(선생의 글 품질이 학습 모델의 상한), Haiku는 기계적 반복 작업. 명령 하나로 끝나는 일은 인라인
- **샘플 문체**: LLM 문체 버릇 4가지를 피한다. 같은 수사 장치 반복(부정 후 재정의, 셋 나열, 짧은 조각 + 복선), 한 가지 특성만 반복하는 납작한 인물, 긴 맥락에서의 설정 어긋남, 감정을 직접 설명하는 것. 한국어 산문에 줄표(—) 금지
- **진행 보고**: 학습과 평가는 사용자가 `watch_train.py` / `watch_eval.py`로 직접 보므로 중간 보고를 하지 않고 끝과 오류만 알린다. 그 밖의 긴 작업(다운로드, 합치기 등)은 단계마다 짧게 보고한다
- **환경 주의**: 12GB에서 학습하려면 `UNSLOTH_CE_LOSS_TARGET_GB=0.5`(스크립트 안에서 지정)와 batch 1 × accum 8이 필요하다. 윈도우 spawn 때문에 학습·평가 스크립트에 `__main__` 가드가 있다. 새로 모델을 받는 스크립트는 unsloth나 transformers를 import하기 전에 `HF_HOME`을 E로 지정해야 한다
